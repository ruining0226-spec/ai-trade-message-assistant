# 第二阶段：接入豆包/火山引擎视觉 AI

## 完整任务范围

在已通过验收的第一阶段基础上，只实现“客户截图识别和客户资料提取”：上传一至五张客户截图，Next.js 服务端读取、校验并轻量预处理图片，调用火山方舟支持图片理解的模型，解析并校验结构化 JSON，在现有第 2 步展示真实结果供人工修改确认，再进入原有第 3 步。

不得接入 Supabase、登录、云存储、网页抓取、社交平台自动化或自动发送；不得重构页面或改变开发信编辑、复制、版本记录、历史任务和 LinkedIn/Facebook/Email/WhatsApp 四渠道功能；开发信生成仍保持模拟。

## 开发与安全要求

- 开发前读取 `AGENTS.md`、`README.md`、`package.json`、`docs/product-requirements.md`、`docs/architecture.md`，定位上传、分析、类型、localStorage、步骤状态和错误提示代码，并保留已有修改。
- 创建 `POST /api/analyze-customer`，使用 multipart/form-data；仅支持 JPEG/PNG/WEBP，单张不超过 10MB，最多 5 张，拒绝空文件、伪造 MIME、超限和无效图片。
- 图片仅在内存中处理；自动修正方向，对过大图片合理缩放压缩，兼顾截图小字可读性；不写入 `public/` 或持久存储，不记录 base64 或完整模型输出。
- 仅服务端读取 `ARK_API_KEY`、`ARK_MODEL_ID`、`ARK_BASE_URL`；模型 ID 不写死；浏览器、日志和错误响应不得泄漏密钥、完整请求、图片或内部堆栈。
- 超时合理；鉴权、余额、参数错误不重试，网络、限流或服务端临时错误最多重试一次；生成请求 ID，前端和服务端共同避免重复提交。

## 模型指令与返回

系统提示词必须把模型定义为 B2B 工业设备外贸客户研究助手：只提取截图明确事实，不将推测写成事实，不虚构姓名、职位、公司、地区、业务、需求或采购意向；未知返回 null/空数组；推测单独标注；冲突列出；区分个人、公司和系统推断；不声称访问截图外网站；谨慎判断压缩空气联系；严格输出指定 JSON。

结构包含客户姓名、职位、公司、国家/地区、行业、公司业务、限定枚举的客户类型和决策影响力、潜在压缩空气应用、推荐切入点、0—100 完整度、不确定信息、冲突与逐项识别依据。服务端必须做运行时结构校验，兼容完整 Markdown JSON 代码围栏，安全补齐非关键缺失字段，完全无法解析或校验失败时返回失败。

## 真实/演示模式与前端体验

- 同时配置 API Key 和模型 ID 时默认真实 AI；缺配置时明确提示“尚未配置豆包/火山引擎API，当前使用演示分析。”并保留现有演示结果。
- 真实调用失败不得暗中返回模拟数据；显示安全原因，并由用户明确点击“使用演示结果继续”。真实与演示结果分别标记 `analysisSource: "volcengine" | "mock"`；旧任务兼容为 `legacy`。
- 分析时依次提示上传、识别文字、分析客户与公司、整理结构化资料、完成/失败，不伪造百分比；禁用重复提交，支持取消，失败可重试且缩略图保留。
- 第 2 步继续使用可编辑表单，标明“AI识别结果，仅供确认”；姓名、职位、公司为重点确认字段；空字段显示手工填写占位；展示完整度、不确定信息、冲突及可折叠识别依据。只有人工确认后的数据能进入第 3 步。
- 上传区显示隐私提示：仅上传工作所需公开客户资料截图，避免身份证、银行卡、私人聊天记录等敏感信息；图片会发送至已配置 AI 服务分析。
