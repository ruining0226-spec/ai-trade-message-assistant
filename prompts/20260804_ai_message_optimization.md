# 当前文案 AI 优化

## 目标

- 在结果页现有操作区附近增加轻量 AI 优化入口。
- 用户可以输入自定义要求，或选择“更简短”“更自然”“更专业”。
- AI 只改写当前可发送英文文案及其中文翻译，成功后覆盖当前结果，不创建版本历史。
- 当前页面会话保留一次优化前快照，可撤销；刷新后不保存撤销状态。

## 数据边界

优化请求只包含：

- 当前渠道；
- 当前消息 id、英文和中文；
- 只由已确认字段构成的简短客户摘要；
- 快捷要求和/或自定义要求；
- 服务端集中企业资料与安全规则。

请求不得包含图片、File、图片 URL、Base64、截图元数据或原始分析请求。优化流程不得调用客户分析接口。

## 保护内容

- 不修改客户事实、客户类型、字段来源、置信度、证据、推测和分析结论。
- 不修改身份分析、业务联系、推荐切入点、个性化依据和不确定信息提示。
- 不新增采购意向、认证、参数、价格、案例、合作关系或其他未确认事实。
- 中文必须忠实对应英文。

## 实现限制

- 复用现有 `ARK_API_KEY`、`ARK_MODEL_ID`、`ARK_BASE_URL`，不增加环境变量。
- 服务端只调用一次火山方舟，不重试，不返回 Mock。
- API 失败时保留原文案并显示安全错误。
- 继续使用 `persistCurrentResult` 单结果覆盖边界。
- 不改变导航、颜色、字体、卡片风格和整体布局；不提交或推送 Git。

## 验收标准

- 自定义和三个快捷要求均进入模型请求。
- 优化成功覆盖当前英文/中文消息且不改变受保护字段。
- 失败时原内容不变，不产生历史版本。
- 撤销恢复优化前内容且不持久化撤销历史。
- 请求 Schema 拒绝图片字段。
- lint、类型检查、自动测试和 build 全部通过。
