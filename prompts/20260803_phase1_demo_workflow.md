# 2026-08-03 第一阶段演示工作流

## 原始任务提示词（完整需求记录）

项目名称：AI 外贸开发信助手；英文目录名 `ai-trade-message-assistant`，使用当前项目文件夹。

项目用于 B2B 空压机海外客户开发。用户上传 LinkedIn 客户资料、公司主页或官网截图后，系统需要分析客户和公司信息、提取结构化资料、允许用户检查修改、生成针对性开发信、支持在线编辑和一键复制、保存客户档案/开发信版本/历史任务，并为后续基于历史记录生成跟进信预留边界。不得删除或改变客户截图分析、针对性开发信生成、开发信编辑与一键复制、历史任务管理四项核心功能。

本次只完成第一阶段，不接真实 AI、Supabase 或云数据库。必须用模拟数据和浏览器 localStorage 完成“上传截图 → 模拟 AI 分析 → 确认和修改客户资料 → 选择生成条件 → 生成示例开发信 → 在线编辑 → 一键复制 → 保存历史记录 → 从历史任务重新打开”的完整可点击闭环，不能只做静态首页。

开发前检查当前目录及文件；若已有项目则阅读结构、README、AGENTS、package.json 和相关源码并在原基础上开发，不重复创建、不覆盖无关代码；空目录才创建 Next.js 项目；保留未提交修改；先汇报检查结果和准备修改的文件。

技术要求：Next.js、TypeScript、Tailwind CSS、App Router、localStorage；推荐组件目录结构；避免不必要的重量依赖；兼容电脑和手机、桌面优先；封装 localStorage，兼容 SSR，避免 window 和 hydration 错误。

界面采用中文专业 SaaS 后台：左侧导航、顶部标题操作区、浅色 B2B 风格、卡片/表格/状态标签/表单，不做普通聊天窗口。导航至少含工作台、新建任务、历史任务、客户管理、公司资料、产品资料、系统设置。

工作台展示今日分析客户数、本周生成开发信数、待发送任务数、待跟进客户数、最近任务和“新建客户分析”按钮，统计来自 localStorage。

新建任务分四步。步骤一支持多图点击和拖拽上传、缩略图、单图删除、常见图片格式、错误格式和过大提示、仅本地预览，并显示“演示模式：暂未调用真实 AI”；分析按钮显示短暂加载。步骤二可编辑客户姓名、职位、公司、国家地区、行业、主要业务、客户类型、决策影响力、潜在压缩空气应用、推荐切入点、完整度和不确定说明；使用 Roger Davis / Managing Director / Laser Industrial Ltd / 激光切割与工业工程等真实业务演示，姓名、职位、公司为重点确认且修改确认后才能继续。步骤三配置渠道（LinkedIn、Email、WhatsApp）、目的（初次认识、寻找经销商、推荐产品、项目合作、二次跟进）、客户类型（经销商、代理商、终端工厂、设备集成商、工程项目方）、语气（友好简短、专业正式、顾问式）、长度（极简、标准、详细）、语言（英文、中英对照）、产品（永磁变频螺杆空压机、两级压缩空压机、无油空压机、整厂节能系统）和补充说明，均存入任务。步骤四用模拟逻辑结合客户姓名、公司、职位、行业和产品，固定展示：客户身份与业务分析、与空压机业务的潜在联系、推荐沟通切入点、LinkedIn 连接邀请、连接后的第一封消息、中文翻译、个性化依据、AI 不确定信息提示。

写作原则：先谈客户行业和业务，再自然联系压缩空气；不直接推销，不虚构需求；体现阅读资料；连接邀请简短友好专业；通过好友后简要介绍我方业务；以自然问题开启交流；根据客户类型调整；不使用夸张营销语言；不虚构认证、案例、参数或合作关系。参考英文为 “Hi Roger, I noticed your experience in industrial engineering and laser cutting…” 以及感谢连接后介绍 Laser Industrial、我方工业空压机和节能系统，并询问是否在激光切割项目中使用或供应压缩空气方案；必须有中文翻译。

结果页支持直接编辑、分别复制连接邀请/第一封消息/全部英文/中英双语、复制成功提示、更简短、更加友好、更加专业、重新生成、保存当前版本、查看旧版本。本地模拟按钮必须可操作；重新生成不覆盖旧版；每次保存或重新生成形成新版本；可切换历史版本；最终选中版本保存到任务。

历史任务至少含唯一 ID、客户姓名/公司/职位/国家/行业/类型、渠道、目的、产品、客户分析、开发信版本、选中版本、创建/更新时间、状态、跟进日期、备注。状态包括待分析、待确认、已生成、待发送、已发送、已回复、待跟进、有效线索、无效客户、已成交、已归档。支持姓名和公司搜索，按状态/类型/渠道筛选，查看详情、继续编辑、复制、改状态、设跟进日期、备注、归档和二次确认删除。

客户管理从历史任务汇总姓名、公司、职位、国家、类型、任务数量、最近联系、状态，以“姓名 + 公司”去重。公司资料可编辑公司名称、简介、优势、服务范围、市场、邮箱、WhatsApp、官网、禁止 AI 说法、不能承诺服务、未确认资质参数。产品资料至少有四种演示产品，每项含名称、简介、行业、应用、优势和禁止虚构信息。公司和产品均存 localStorage。

至少建立 Customer、CustomerAnalysis、Task、TaskImage、MessageVersion、CompanyProfile、Product、FollowUp 类型；代码分 app、components/layout、dashboard、task、customer、message、ui、lib/mock、storage、utils、types、docs、prompts，避免所有逻辑挤在单页。

创建 README、AGENTS、产品需求、架构文档和本提示记录。AGENTS 规则包括：明确范围、修改前读文件、不改变四项核心功能、不擅删功能、不写 API 密钥、.env 不提交、数据库用 migration、AI 输出结构校验、区分演示与真实数据、大修改记入 prompts、完成后跑 Lint/类型/测试、Git 只处理当前项目。

暂不开发 LinkedIn 自动登录/抓取/发送、邮件群发、浏览器插件、团队权限、复杂 CRM、付费、手机 App、真实 AI、Supabase 和云部署，但保留清晰扩展边界。

界面要求中文、专业清晰现代、适合 B2B 内部工具、可读对比度、明确标签、加载/成功/失败/禁用状态、空数据引导、少渐变和无关动画、内容合理分页面、手机不严重横溢。

验收：依赖可安装启动；所有导航可打开；多图预览；模拟分析；资料修改确认；选择生成条件；生成参考风格中英文；在线编辑复制并反馈；重新生成保留旧版；刷新保留历史；可重新打开编辑；搜索筛选；状态/日期/备注；公司产品保存；无明显 TypeScript/Lint/运行错误；基本响应式。

执行时自主完成，只有重大冲突、重要覆盖、账号密钥权限、无法保留修改或重大产品方向选择才暂停。完成后汇报功能、关键文件、启动方法、地址、检查结果、模拟部分和下一阶段建议；不执行 Git 提交或推送。
