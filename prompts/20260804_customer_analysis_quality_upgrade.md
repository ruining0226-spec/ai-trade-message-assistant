# 客户分析与英文开发信质量升级

## 本轮目标

- 提高截图客户信息的可核验性，为关键字段记录来源、证据、置信度和人工确认状态。
- 将截图事实与 AI 推测彻底分离，潜在需求必须说明判断依据。
- 根据客户类型生成自然、谨慎的英文开发信及忠实中文翻译。
- 在现有四步任务流中清楚展示截图事实、AI 推测和待确认信息。

## 限制

- 继续只使用现有火山方舟豆包模型，不接入 DeepSeek 或其他模型。
- 每轮截图分析严格只发起一次模型请求；网络或上游故障直接返回安全错误，不自动追加第二次调用。
- 不增加向量数据库、复杂知识库、自动发送或批量群发。
- 不改动无关页面，不删除任务创建、图片上传、任务保存、编辑和复制功能。
- 不读取、记录、显示或提交任何 API Key；不提交或推送 Git。
- 企业配置只使用仓库中已有且可确认的内容，演示公司名称、示例联系方式和未确认企业优势不作为真实资料。

## 主要修改项

1. 为姓名、职位、公司、国家/地区、行业、客户类型和其他重要信息采用统一字段结构：`value`、`source`、`evidence`、`confidence`、`needsReview`。
2. 增加独立 `inferences` 数组；推测包含内容、依据和置信度，不得写成截图事实。
3. 客户类型限制为 distributor、agent、end_user_factory、oem_integrator、service_provider、unknown，并要求分类证据。
4. 在 `config/company-profile.ts` 集中维护企业事实边界、产品类别、客户类型切入点、禁止声明、写作规范和联系方式。
5. 同一个豆包 JSON 响应返回英文主题、中文主题、80–120 词英文正文和忠实中文翻译。
6. 对模型邮件增加安全选择：长度不合格、包含禁用断言或引用低置信度姓名/公司名时使用安全本地模板，不追加模型请求。
7. 页面以文字标签展示来源、置信度和“需要确认”，并单独展示推测及依据。
8. 为旧任务保留缺省兼容路径。

## 验收标准

- 未识别信息安全回退为 null/unknown，不作为确定事实。
- 截断公司名或职位为 low 且 needsReview=true。
- 推测仅进入 inferences；证据不足时客户类型为 unknown。
- 开发信不声称客户正在采购，不使用低置信度公司名，正文基本保持 80–120 词。
- 英文和中文消息能够保存、打开、显示和编辑；旧任务不崩溃。
- 真实 API 失败不返回 Mock 分析。
- lint、TypeScript 类型检查、自动测试和 build 全部通过。
- 正常分析仍只有一次火山方舟 API 请求。
